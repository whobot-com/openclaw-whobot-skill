# 账号与登录

入口：`whobot login --phone <手机号>`、`whobot logout`、`whobot reset` 分别登录、退出、重置。先取确认卡，不加确认参数。查余额用 `whobot balance`，照 `data.totalBalance` 说"企业账户总余额 X（含付费、赠费和信用额度）"，不估算、不换算；未登录时按返回的 `login` 先登录。

## 用户会这样说

- 登录呼波特。
- 换一个账号。
- 我想退出登录。
- 清除本机账号。
- 为什么显示已登录却不能用？
- 账户里还有多少钱？

## 先弄清楚

确认要登录、退出还是重置。登录时先展示 CLI 返回的隐私协议和用户协议链接；不要从 Skill 或旧消息补链接。

## 标准流程

1. 未登录的受保护命令会返回 `next.action=login`。先按本次 `next.confirm` 展示协议链接和同意说明，再调用宿主结构化提问工具完成登录确认；用户主动登录返回 `next.action=confirm` 时也使用这一方式。
2. 已知手机号时，工具选项为“同意，用尾号 XXXX 登录 / 换个号码 / 暂不登录”；尚未提供手机号时为“同意并继续 / 暂不登录”，同意后收集手机号。选择换号时收集新号码并重新取得对应确认；选择暂不登录则结束本次登录。收到用户明确同意后，才执行本次返回的 `next.command`，其中 `{phone}` 用用户提供的完整手机号替换。
3. 按 `next.ask` 询问验证码，替换 `{code}` 后执行系统命令；成功后返回 `run`，只执行最新 `next.command` 一次续做原任务。此前的 `next.resume` 是恢复目标说明，不再另执行一次。完整链路见 [protocol](protocol.md)。
4. 用户主动登录时，先执行 `whobot login --phone <手机号>`，返回确认信息后按第 1–2 步调用提问工具；取得同意后再执行其中的命令。
5. 状态只读使用 `whobot status`；退出或重置先运行对应入口，用户同意后执行系统返回的确认命令。

## 话术

正文展示本次协议链接和“继续登录即表示同意”，使用宿主结构化提问工具收集选择与确认，调用后等待用户回答。宿主没有可用的结构化提问工具时，按根指引改用编号选项。登录手机号使用后四位描述，例如“确认使用尾号 8951 的手机号登录吗？”“请提供尾号 8951 收到的登录验证码。”实际登录使用本次用户提供的完整手机号。验证码只用于本次登录，不复述。错误或过期仍按 `next` 处理：`ask` 才询问，`stop` 则停止。服务配置异常时转述系统文案，不承诺稍后恢复。

## 常见岔路

用户换企业或状态为 `needs_reset` 时停止当前操作，运行重置入口并展示确认卡。状态不确定时查询 `whobot status`；不猜验证码、不循环提交、不把本地缓存当登录事实。

## 绝不

- 不展示验证码、Token 或完整手机号。
- 不在没有确认时退出或重置。
- 不把本机缓存当登录事实。
- 不自行构造 `--accept-terms`、`--yes` 或其他确认参数，只执行上一条输出的 `next.command`。
