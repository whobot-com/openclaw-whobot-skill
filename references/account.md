# 账号与登录

入口：`whobot login`、`whobot logout`、`whobot reset` 分别登录、退出、重置。先取确认卡，不加确认参数。查余额用 `whobot balance`，照 `data.totalBalance` 说"企业账户总余额 X（含付费、赠费和信用额度）"，不估算、不换算；未登录时按返回的 `login` 先登录。

## 用户会这样说

- 登录呼波特。
- 换一个账号。
- 我想退出登录。
- 清除本机账号。
- 为什么显示已登录却不能用？
- 账户里还有多少钱？

## 先弄清楚

确认要登录、退出还是重置。登录时先展示 CLI 返回的隐私协议和用户协议链接；不要从 Skill 或旧消息补链接。

## 标准流程

1. 未登录的受保护命令和不带参数的 `whobot login` 返回 `next.action=login`；带手机号的 `whobot login --phone <手机号>` 返回 `next.action=confirm`。两种情况都先在正文完整展示本次 `next.confirm`：标题、协议链接和全部 `notes`。`notes` 中的新注册用户赠送说明与计费说明必须逐条原文展示，不删减、不改写、不合并，并用醒目格式呈现（如加粗小标题加引用块），不能折叠在一句话里带过。
2. 登录确认这一步不调用宿主结构化提问工具，也不给编号选项，展示完后请用户看完再手动回复，然后结束本轮等待。已知手机号时说"看完后回复「继续」即用尾号 XXXX 登录；要换号码请直接发新号码；暂不登录请回复「不登录」"；尚未提供手机号时说"看完后请直接回复要登录的手机号；暂不登录请回复「不登录」"。用户发新号码时重新取得对应确认并再次完整展示；回复不登录则结束本次登录。收到用户手动回复的明确同意后，才执行本次返回的 `next.command`，其中 `{phone}` 用用户提供的完整手机号替换。
3. 按 `next.ask` 询问验证码，替换 `{code}` 后执行系统命令；成功后返回 `run`，只执行最新 `next.command` 一次续做原任务。此前的 `next.resume` 是恢复目标说明，不再另执行一次。完整链路见 [protocol](protocol.md)。
4. 用户主动登录时，不论是否已给手机号，都先执行不带参数的 `whobot login`，不要先向用户要手机号；返回确认信息后按第 1–2 步完整展示并等待用户手动回复。用户已经给了手机号时，展示后按“已知手机号”的说法请用户确认；取得同意后再执行其中的命令。
5. 状态只读使用 `whobot status`；退出或重置先运行对应入口，用户同意后执行系统返回的确认命令。

## 话术

正文展示本次协议链接、“继续登录即表示同意”和醒目的新注册用户赠送与计费说明，请用户看完后手动回复，不调用结构化提问工具。登录手机号使用后四位描述，例如“确认使用尾号 8951 的手机号登录吗？”“请提供尾号 8951 收到的登录验证码。”实际登录使用本次用户提供的完整手机号。验证码只用于本次登录，不复述。错误或过期仍按 `next` 处理：`ask` 才询问，`stop` 则停止。服务配置异常时转述系统文案，不承诺稍后恢复。

## 常见岔路

用户换企业或状态为 `needs_reset` 时停止当前操作，运行重置入口并展示确认卡。状态不确定时查询 `whobot status`；不猜验证码、不循环提交、不把本地缓存当登录事实。

## 绝不

- 不展示验证码、Token 或完整手机号。
- 不在没有确认时退出或重置。
- 不把本机缓存当登录事实。
- 不在登录确认时调用结构化提问工具，不省略或改写 `next.confirm.notes`。
- 不自行构造 `--accept-terms`、`--yes` 或其他确认参数，只执行上一条输出的 `next.command`。
