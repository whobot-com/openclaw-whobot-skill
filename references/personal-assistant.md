# 个人助理（Personal Agent）

个人助理面向个人用户，替用户给别人打电话办事；现在能办哪些事，以 `whobot assistant list` 返回的个人助理为准。它是单独的一套用法，不走标杆试打；标杆列表里也能看到同一个员工，那里按 [try-a-call](try-a-call.md) 普通体验，不会替用户直接打给别人。

入口命令（`<agent>` 使用列表返回的引用，不向用户展示）：

```text
whobot assistant list
whobot assistant show <agent>
whobot assistant call <agent> --attr <name>=<值>
whobot assistant call <agent> --phone <对方号码> --attr <name>=<值>
whobot assistant call <agent> --attr-login-phone <name> --attr <name>=<值>
whobot assistant balance
whobot assistant recharge
```

## 现在能做什么

- 替用户打电话办事：每个个人助理办一类事，要收集哪些信息、怎么办，写在它的说明书里（详情的 `guide`）。
- 回电号码可以直接用用户的登录手机号。
- 打完给出接听情况、通话摘要、完整文字对话和录音；接通的电话还给出网站上这一单的记录链接。
- 计费：接通才计时，按通话时长扣个人助理的分钟（不足 1 分钟按 1 分钟），没接通不扣；新用户送分钟。单价和剩余分钟以确认卡、余额查询的返回为准。
- 次数：登录手机号不限代拨次数；同一个号码每天被代拨的次数有上限，以返回为准。

## 用户会这样说

- 帮我给这家店打电话订个位。
- 用个人助理替我打个电话问一下。
- 个人助理还剩多少分钟？给个人助理充点分钟。
- 个人助理的钱怎么退？代拨记录和录音在哪看？

## 标准流程

1. 运行 `whobot assistant list`，按用户要办的事选个人助理：只有一个能办时直接用它；有多个时拿不准就用选择卡问；没有能办这件事的，如实说现在还不支持，不拿别的个人助理凑。
2. 运行 `whobot assistant show <agent>`。本次对话第一次进入个人助理时，先照下面这段向用户介绍，花括号处按列表里个人助理的名称和简介写出现在能办的事，链接完整给出；介绍和第 3 步要问的信息放在同一次回复里。同一次对话里再用个人助理时不再介绍。

   > 我是呼波特个人助理，能替你打电话把事办成，现在可以帮你{能办的事}。你说清要办的事，我来拨打，打完把结果、录音和文字对话发给你。接通才计费，按分钟扣个人助理的余额。代拨记录、充值和设置都在网站 https://dingcan.whobot.com/ ，用同一个手机号登录。

3. 详情有 `guide`（说明书）时按它向用户收集和确认信息，说明书没要求问的项不用问；没有说明书时逐项确认 `trialAttributes`，没有 `default` 的每一项都要问到。`default` 是用户在呼波特订餐里的设置（回电号码没设置时就是登录手机号）：用户没提的项不追问、不用传，系统按设置补上，确认卡上会显示，用户要改再按用户说的传。缺的信息合并成一次问完，日期时间换算成具体日期和时刻。回电号码按 `label` 找到那一项：用户没提时不追问，按 `default` 带上；用户说留登录手机号时传 `--attr-login-phone <这一项的 name>`，给了其他完整号码时传 `--attr <name>=<号码>`；不填脱敏号码或尾号。
4. 运行 `whobot assistant call <agent> --attr ...`（对方号码见下方“代拨号码”），之后严格按本次返回的 `next` 走：`confirm` 原样展示确认卡（含全部 notes；余额不足 5 分钟时 notes 里有充值建议，用户要先充值就按下方“充值”办理，充好后重新运行代拨命令取新的确认卡），用户确认后执行 `next.command`；`ask` 带选项时用选择卡让用户选，只把选中项的 `value` 替换进命令；`stop` 或错误时原样转述 `userMessage`，等用户补充或更正，不换属性名、号码写法、账号或个人助理绕过。
5. 确认后返回 `wait` 时立刻原样运行 `next.command`，直到 `done`、`handoff` 或 `stop`；不问用户、不让用户挂断后再来告知。通话通常 1 到 10 几分钟，宿主命令超时设 130 秒以上。
6. 讲结果：先说接听状态 `answerMainStatusText`、`answerStatusText`；有 `result.call` 时说时长 `durationText`，并在同一次回复里展示通话摘要 `result.call.summary` 和完整文字对话（按 `result.call.transcript` 原顺序逐句展示 `text`，`role=assistant` 标为“个人助理”，`role=user` 标为“对方”），不截断、不用摘要代替，为空时如实说明，不编造。录音按 [try-a-call](try-a-call.md) “话术”里的录音规则交付。有 `data.assistant.recordPageUrl` 时，最后给出这一单在网站上的记录链接，链接完整给出，说明用同一个手机号登录后查看。没打通时如实说接听状态，再转述 `suggest` 里没有命令的那条建议，只建议稍后再试。
7. 余额提醒：`suggest` 里有充值建议（命令是 `whobot assistant recharge`）时，讲完结果后转述它的 `say`，问用户要不要现在充值；要的话按下方“充值”办理，不替用户决定。

## 代拨号码

号码从哪来按说明书：有的个人助理由系统按名称和区域查号（这时不带 `--phone`），有的要用户给号码。

- 系统查到多家、返回选择时，用选择卡让用户选，只把选中项的 `value` 替换进命令。
- 系统返回查不到或查询暂不可用时，转述返回的提示，再按说明书处理。
- 号码是你自己查到的：把号码和来源告诉用户，用户确认后，重新运行 `whobot assistant call <agent> --phone <号码> --attr <name>=<值>`，其他信息照常带上。
- 不编号码、不猜号码，不用来源不明的号码；换一个号码再打之前先问用户。

## 余额与充值

个人助理代拨扣的是个人助理的分钟，按登录手机号单独计，和企业账户余额是两本账（区别见 [account](account.md) 的“查余额”）。

查余额：运行 `whobot assistant balance`，照 `data.availableMinutes` 说“个人助理还剩 X 分钟”，需要时补一句单价 `data.price`。`data.debtMinutes` 大于 0 时说“上次通话超出余额，欠 Y 分钟，充值后会先抵扣”。不足 1 分钟时命令会返回充值方式的选择，按下面的“充值”办理。

充值：代拨时返回分钟不够或欠费（错误 `INSUFFICIENT_BALANCE`），查余额不足 1 分钟，确认卡或代拨结果建议充值且用户同意，或用户主动要充值（运行 `whobot assistant recharge`）。

1. 先转述返回的 `userMessage`（如有），再按 `next.ask` 用选择卡让用户选充值方式（去网站充值 / 微信支付 / 支付宝），把选中项的 `value` 替换进命令执行。
2. 选“去网站充值”：转述 `next.say`，链接完整给出，结束本轮。
3. 选微信或支付宝：返回档位选择卡（只列充值后够打一通电话的档位），用户选定后替换进命令执行。
4. 下单后在正文先用 Markdown 图片显示付款码（地址取 `data.qrImageUrl`，替代文字写“扫码付款”），下一行给付款页链接（地址取 `data.payUrl`，链接文字写“打开付款页”），再转述 `next.say`，结束本轮等用户付款。图片和链接原样使用返回的地址，不改写、不缩短；图片显示不出来时，请用户点付款页链接，或用手机打开付款。
5. 用户说付好了，执行上一步 `next.command` 查是否到账：
   - 到账（`next.action=done`）：转述 `suggest[0].say`，再问要不要接着发起刚才的代拨；要的话重新运行刚才的代拨命令，取新的确认卡，不沿用旧卡。
   - 还没到账（`handoff`）：转述 `next.say`，等用户再说，不自己反复查。
   - 已过期（`stop`）：转述 `next.say`；用户还要充值时从第 1 步重新开始。

## 网站、记录、退款与发票

个人助理有自己的网站 <https://dingcan.whobot.com/> ，用登录呼波特的同一个手机号、短信验证码登录，这里代拨的电话都能在网站上看到。网站上可以：

- 概览：剩余分钟和最近的代拨记录。
- 订位记录：每通代拨电话的结果、录音和文字对话，可以删除某一单的录音和对话；觉得结果或计费不对，在那条记录里点「结果不对？告诉我们」。
- 钱包：充值（微信、支付宝）、看充值记录、申请退款、看退款进度。
- 设置：打电话时用的信息（如称呼、回电号码、开场白），代拨时会用作默认信息；短信通知；更换手机号；已授权的 AI 助手；导出个人信息、注销账号。
- 帮助中心和《计费与退款规则》。

网站上不能发起代拨，代拨在对话里发起。

退款：对话里不能退款。用户要退款时，引导去网站钱包页 <https://dingcan.whobot.com/app/wallet> 点「申请退款」，按网站规则处理：没用完的充值分钟按充值时的单价原路退回（退到微信零钱一般几分钟到账，退到银行卡 1–3 个工作日）；赠送的分钟不能退；通话进行中不能申请，结束后再申请；申请没通过时钱包页会显示原因。完整规则见 <https://dingcan.whobot.com/legal/terms#pricing> 。

发票：需要发票时，在网站钱包页点「联系客服」，提供充值订单号（钱包的充值记录里能看到）和开票信息，客服核实后开电子普通发票。

## 绝不

- 不打给用户本人的号码，不编号码，不自动重拨。
- 号码当日次数用完时只转述，不换号或换账号重试。
- 不替用户选充值方式或档位，不在用户没选时下单，不重复下单；查询结果不是到账就不说已到账。
- 不把个人助理的分钟和企业余额混在一起说；个人助理的充值、退款、发票不给企业管理平台、财务资金中心或发票管理的链接。
- 不说对话里能退款；不展示订单号，不改写付款码或付款页地址。
