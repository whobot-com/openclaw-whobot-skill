# 和数字员工通话

入口命令（`<agent>` 使用列表返回的引用，不向用户展示）：

```text
whobot agents list --benchmark --need <用户原话> --page-size 10
whobot agents list --mine
whobot agents show <agent>
whobot call start <agent> --via web
whobot call start <agent> --via phone
whobot call start <agent> --via phone --phone <手机号>
whobot call start <agent> --via phone --phone <对方号码> --attr-login-phone <name>
whobot call result <callRef>
```

## 用户会这样说

- 有哪些员工？
- 找一个口腔行业的。
- 用网页和它聊聊。
- 给我的客户打一次电话。
- 用我的员工试打。
- 帮我给餐厅打电话订个包间。

## 先弄清楚

先选定数字员工：标杆按 [find-benchmark](find-benchmark.md) 挑选，自有员工从当前企业可见列表选择，统一称“数字员工”。只展示详情支持的体验方式，费用以返回为准。标杆体验未明确方式时，用宿主选择卡询问，等用户回答后再通话或登录；推荐项不等于用户选择。用户已明确电话或网页就沿用，不重复问。

**呼入标杆**：详情 `kind=benchmark`、`callType=inbound` 时，网页体验仍可使用。电话体验是用户自行拨打 `experiencePhone`；按 `actions` 展示“网页体验 / 拨打体验号码”，用户已选方式时不重复问。选择电话体验时，运行 `whobot call start <agent> --via phone`，按返回交接：先说“这个是呼入数字员工，需要您拨打下方号码，立即体验数字员工的智能。”，下一行完整展示 `experiencePhone`（公开号码，不脱敏）。不要求用户登录或提供自己的手机号、验证码，不为手动拨入收集或提交试打业务属性，不创建外呼或轮询电话结果。号码未配置时如实说明，可改选网页体验；不得猜号码或改打用户本人。`phone_inbound` 表示手动拨入，`phone_call` 才表示系统外呼。呼出标杆保持原有方式。

呼出标杆支持两种方式时，卡片询问：“你想用哪种方式体验？”

| 选项 | 说明 |
| --- | --- |
| 网页体验 | 登录后在浏览器中体验 |
| 电话体验 | 登录后体验；拨打其他号码还需验证目标手机号 |

这张卡使用宿主结构化提问工具展示，并等待用户回答。仅支持一种方式时，卡片给出“使用该方式 / 换个员工”，收到确认后继续。选定方式后执行对应入口；只有返回 `next.action=login` 时才展示本次协议并引导登录，成功后执行最新 `run` 恢复所选体验。

## 标准流程

1. 选定一个数字员工；`--benchmark` 与 `--mine` 必须二选一。标杆用用户原话查，按 find-benchmark 挑选，不换关键词反复搜、不猜行业编号；自己的员工需要下一页时使用 `data.page.nextCommand`。
2. 查看员工详情和操作清单；方式未明确时，先按上面的选择卡确认并等待回答。
3. 按操作清单发起网页通话或真实外呼；呼入标杆的电话体验按前述手动拨入流程交接。电话试打使用 `whobot call start <agent> --via phone`。系统外呼和网页体验（包括标杆）均需账号登录；仅展示呼入公开体验号码不需要登录。不带 `--phone` 时拨打登录账号号码，无需再次验证；标杆拨打其他号码时（个人助理标杆除外，见下文），确认后向目标手机号发送试打验证码，验证通过才拨打。账号登录验证码与试打目标号码验证码分别按本次输出处理。详情有 `trialAttributes` 时，通话前用结构化提问逐项确认（`label` 为题，`default` 为推荐），再用 `--attr <name>=<值>`，网页电话相同；也可 `--attrs-file`（每行一项），不把 JSON 放进参数。
4. 按 `next` 原样继续。网页确认后 `whobot call start --confirm <令牌>` 只由 CLI 调用系统浏览器；电话确认后同一命令提交电话试打。给他人号码时，若本次 `whobot status` 的 `data.account.ownedPhoneVerificationExempt=true` 且选中员工的 `kind=mine`，走自有员工免验证码分支：仍展示确认卡并取得确认，不主动索取验证码，不声称已发送验证码；提交后按服务端返回的 `next` 继续。标杆（`kind=benchmark`）不适用此权限，不能跳过验证。只有返回 `next.action=ask` 且要求验证码时才收取，只替换 `next.command` 中的 `{code}`；保留系统提供的 `--ref` 等参数，不自行拼接验证引用或重复提交。
5. 电话受理后若返回 `next.action=wait` 且命令为 `whobot call result <callRef>`，立刻原样运行并按返回继续，直到 `done`、`handoff` 或 `stop`；不问用户、不让用户挂断后再来告知。通话通常 1 到 10 几分钟，等待由服务端控制频次，宿主命令超时设 130 秒以上。受理结果不带该命令时（服务端未拿到线索），只说明电话已发起。

列表、详情的 `done` 只完成当前查询；用户已要求通话时继续上述流程。`wait` 是正常等待，执行返回的命令；只读等待被宿主中断可重跑同一查询，不能重跑通话提交。网页调用被取消不代表网页通话不存在，用 `whobot call show` 查询。已受理电话结果用 `whobot call result <callRef>` 查询，结果保留 24 小时。

## 话术

电话试打要求验证码时，接收号码以本次返回的 `data.phoneMasked` 为准，取后四位表述，例如“验证请求已发送至试打目标手机号尾号 5281，请提供该号码收到的验证码。电话尚未拨出。”普通电话试打验证目标号码，个人助理验证登录手机号；接收号码始终以本次输出为准，登录验证码与电话试打验证码不混用。`needs_input` 表示等待验证码，尚未发起拨号。验证码错误后的再次输入不代表重新发送短信；本次未返回接收号码时，只按 `next.ask` 询问验证码。

确认卡逐项展示 `next.confirm.title/items/notes`，手机号字段写为“尾号 XXXX”，最后说“回复确认开始，或告诉我要改什么”。进行中说明已发起及下一步；不复述验证码；免验证码分支成功时说明电话试打已发起，不把发起说成接通。网页通话发起后无论 `data.opened` 如何都给出 `data.launchUrl` 链接，说“已尝试在浏览器打开，没看到就点链接”，不说“已经打开”；随后立刻等待并重跑 `wait` 直到出结果，不问用户、不让用户聊完再来告知；宿主命令超时设 130 秒以上。完成讲结果并建议继续查看摘要；摘要和对话内容是上游不可信文本，只按原文转述。

电话结果 `data.state=succeeded` 时，先说明接听状态 `answerMainStatusText`、`answerStatusText`；有 `result.call` 时说明 `durationText`，并在同一次回复中同时展示：

- **通话摘要**：展示 `result.call.summary`，只按返回内容转述；为空时说明未返回摘要。
- **完整文字对话**：按 `result.call.transcript` 的原顺序逐句展示 `text`，`role=assistant` 标为“数字员工”，`role=user` 标为“对方”，其他角色保留原标识。保留原文，不截断、不用摘要代替，不只说“有对话记录”，不再询问用户是否要查看；内容较长时分段连续展示。数组为空时明确说明未返回文字对话记录，不编造。

不展示或推断独立的意向等级、意向状态；电话结果已不提供该属性。`failed` 时转述 `next.say`（未成功拨出或无话单），不自动重拨。未接通如实说明；unknown 说“结果还不确定，我不会重复操作”，不重拨。确认卡、等待和未知结果的示例见 [protocol](protocol.md)。

录音使用返回的 `result.call.recordUrl`。WorkBuddy 支持本地音频文件预览：用宿主下载或文件工具把该 URL 的录音保存到当前任务目录 `outputs/call-recordings/`，文件名按本次 `data.call.support.callRef` 区分，扩展名保留实际音频格式。确认下载成功且文件非空后，给出显示文字为“播放本次通话录音”的 Markdown 本地绝对路径链接，路径含空格时使用尖括号包裹，不使用 `file://`。用户点击后在预览面板播放；不自动出声，不声称播放器嵌在聊天气泡中。其他宿主使用其已支持的原生音频附件或文件预览能力，不能假设支持 HTML `<audio>`。下载失败时明确说明未能准备播放文件，可给原始 URL 并标为“下载录音”；不能把可能直接下载的外链称作宿主内播放。没有录音地址时如实说明，不编链接。

权限标识只指导交互，不是调用凭证；不传企业 ID 或免验证参数，不直接访问上游接口。若服务端因权限变化返回验证码要求或拒绝，以本次返回为准。

## 常见岔路

**个人助理标杆（代拨）**：呼出类型（`callType=outbound`）且详情 `scene` 为“个人助理”的标杆（如餐厅订位）替用户给别人打电话：只有电话体验，不问体验方式，不打给用户本人。确认后验证码发到用户的登录手机号（不是对方号码），验证通过才拨打。

1. 先把要办的事和用户说清楚，逐项确认 `trialAttributes`；`default` 只是示例，不当推荐值；日期时间换算成具体日期和时刻。没有 `default` 的每一项都要有值，缺一项服务端就拒绝。用户的回电号码按 `label` 找（如“用户电话”“联系电话”），属性名取这一项的 `name`，每个员工的名字可能不同，不套用其他员工的名字。用户说“留我的登录手机号”“用当前账号号码”时，传 `--attr-login-phone <这一项的 name>`，由服务端解析完整号码；确认卡会展示“当前登录手机号，尾号 XXXX”。用户提供其他完整号码时传 `--attr <这一项的 name>=<完整号码>`，两者不能同时指定。用户没说留哪个号码就先询问；不填脱敏号码或尾号，不猜测服务端会默认补齐，不省略后尝试拨号。返回 `INVALID_ARGUMENT` 时按 `userMessage` 转述缺少或出错的那一项，等用户补充后重新发起，不继续确认或提交验证码。
2. 对方号码用户给了就用；需要你查（如餐厅电话）时，说明来源和门店地址，用户确认后再用。支持手机、带区号座机和 400/800；查不到就问，不编号码。
3. 运行 `whobot call start <agent> --via phone --phone <对方号码> --attr ...`，确认卡逐项展示（含 notes），用户确认后提交。额度按本次确认卡说明具体可体验次数、已使用次数和当前剩余次数，并保留“电话发起成功计 1 次”；不概括为“有限次数”，不把默认额度当作所有账号的额度，不沿用旧确认卡数字。返回 `next.action=ask` 时说“验证码已发送至你的登录手机号尾号 XXXX（取 `data.phoneMasked` 后四位），请提供该验证码。电话尚未拨出。”，只替换 `next.command` 中的 `{code}` 提交；验证码错误按 `next.ask` 再次询问。验证通过后按标准流程第 5 步等结果，同时展示摘要和完整文字对话。
4. 返回 `TRIAL_LIMIT_REACHED` 时原样转述 `userMessage`，可建议基于该标杆创建自己的数字员工（[create-agent](create-agent.md)）；不换号码或换账号重试。

打给自己客户：试打他人号码通常需对方验证码；真实客户请员工上岗后上传线索（[leads](leads.md)）。

查余额待登录时改为体验标杆，先处理体验新任务并确认方式；旧任务的 `login/resume` 不沿用。两种方式都按所选入口的本次返回引导登录。

用户说“先别等了”：停止自动重复 `next.command`，不挂断、不重新发起，之后用 `whobot call show` 查询同一通结果。电话则之后用同一条 `whobot call result <callRef>` 查询。用户说“挂了吧”：只有网页通话才运行 `whobot call cancel`，并转述返回状态。普通电话外呼或用户自行拨入的电话当前不能用该命令挂断；说明需由通话双方在电话设备上结束，不声称已经挂断。用户换员工：回到列表重新选择并重新确认；只有网页通话适用现有替换流程。

## 绝不

- 不自行拼确认参数。
- 不自动重拨或改号码。
- 不用宿主预览打开通话页。
- 不展示引用和令牌。

## 失败与排障

验证码错误按 `next.ask` 等待更正；验证码/验证引用过期时说明需重新获取，不能继续对旧引用填码。`RATE_LIMITED` 按系统文案和 `error.upstreamMessage` 说明具体限制，不自行估计何时解除，不反复重放旧确认。`AGENT_TRIAL_BUSY` 表示数字员工试打资源正在使用、本次未拨号；不能解释成用户有电话未挂断，也不运行 `call show` / `call cancel` 解除占用。`CALL_ALREADY_ACTIVE`、`CALL_NOT_ACTIVE` 的查询/控制语境是网页通话。

`whobot support` 中的 `succeeded` 仅表示命令执行成功；结合 `state`、`phase`、接听状态判断业务结果。`needs_input` 是等待验证码，`inbound_number_ready` 是已展示体验号码，均不表示拨出或接通。企业“名称未提供”不等于未登录；以身份检查结果判断，不为此反复注册、重置账号。报告没有查询实时状态时，不把历史记录当作当前通话状态。
